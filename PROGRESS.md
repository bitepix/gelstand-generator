## Решения по ходу
- Все четыре поля (ширина, глубина, Nx, Ny) хранятся строками, включая количество: они приходят из одинаковых текстовых инпутов (ТЗ 17.1).
- Редьюсер ничего не нормализует и не проверяет. `normalizeField` получает уже нормализованную строку: `normalize` вызывается до `dispatch`.
- Полей ошибок в дереве состояния нет: `validate(state)` — чистая функция, результат считается на месте вызова. Хранить его смысла нет, а расхождение состояния с полями так невозможно.
- `generateOk(model, snapshot)` принимает снимок параметров явно.
- `snapshot` кладёт форму ячейки первым полем — на случай круглой в бете.
- ERR-07 отдельным кодом не возвращается: по таблице 16 у него нет своего текста, это ситуация «в блоке одновременно ERR-05 и ERR-06». `validate` отдаёт `['ERR-05', 'ERR-06']`.
- Пустое поле `normalize` не заполняет — иначе ERR-01, ERR-03 и ERR-04 никогда бы не сработали. Пустая строка остаётся пустой, ошибку ставит `validate`.
- Мусор в поле («мм», пробелы) приравнен к пустому.
- Габарит по оси проверяется только если оба её поля прошли ERR-01…ERR-04: к пустому полю не добавляется шум про габарит.
- Дробное количество ячеек по букве таблицы 5.1 даёт `1`, а не округление: `2,7 → 1`. Выглядит резко, но так написано в ТЗ — если имелось в виду округление, поправить в A2 одной строкой.
- Тесты — встроенный раннер node, без зависимостей: `npm test`. Проверка редьюсера — `npm run check:state`.
