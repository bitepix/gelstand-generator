# ТЗ: онлайн-генератор Nail Modernism Gelstand

**Версия 3, альфа.** Геометрия подтверждена по STEP-экспорту реальной модели. Круглая форма ячейки отложена за пределы альфы. Отличия от версии 2 — в разделе 23.

---

# 1. Назначение

Онлайн-генератор 3D-моделей подставок под баночки. Пользователь задаёт размеры баночки и количество ячеек, получает готовую модель и скачивает файл для печати.

- Авторизация и регистрация не требуются.
- Интерфейс русский.
- Единый последовательный интерфейс без отдельных страниц на каждый шаг.
- Приложение полностью клиентское, серверной части нет.

## 1.1 Рамки альфы

В альфе поддерживается **только прямоугольная форма ячейки.**

Переключатель формы отображается с обоими пунктами. Пункт «Круглая» неактивен и помечен бэйджем **Soon**. Нажатие на него не меняет состояние приложения.

Причина: круглая ячейка требует гексагональной упаковки, при которой у ячейки шесть соседей и прямоугольная плитка не существует. Это отдельный алгоритм и отдельная модель в Fusion, которой пока нет.

---

# 2. Пользовательский сценарий

**Шаг 1 → Шаг 2 → Шаг 3.** Возврата на предыдущий шаг нет.

Третий шаг содержит все параметры первых двух, поэтому шаги 1 и 2 — вводный сценарий, а шаг 3 — основной рабочий экран.

На третьем шаге доступен полный сброс: подтверждение → удаление данных → возврат на шаг 1 с начальными значениями.

---

# 3. Начальные значения

| Параметр | Значение |
|---|---|
| Форма | Прямоугольная (единственная активная) |
| Ширина | 19,6 мм |
| Глубина | 37,0 мм |
| Nx | 3 |
| Ny | 3 |

Начальные размеры соответствуют исходной модели, с которой снята геометрия. Такой пресет сразу даёт корректную и проверенную в печати подставку.

---

# 4. Шаг 1 — размеры баночки

Переключатель формы: «Прямоугольная» активна, «Круглая» неактивна с бэйджем Soon.

Два поля: Ширина, мм; Глубина, мм. Допускаются неравные размеры.

Пользователь вводит **размер полости под баночку.** Зазор на посадку не добавляется: введённое значение равно расстоянию между стойками в готовой модели.

---

# 5. Правила ввода размеров

Диапазон **10–100 мм включительно.** Дробные значения, максимум 2 знака после запятой. Лишние знаки округляются **в большую сторону.**

Десятичный разделитель — запятая. Ввод `20.5` преобразуется в `20,5`.

## 5.1 Автоматические исправления

Не считаются ошибками, срабатывают по завершении ввода:

| Ввод | Результат | Правило |
|---|---|---|
| `20.5` | `20,5` | Точка всегда заменяется на запятую |
| `20,5678` | `20,57` | Округление до двух знаков в большую сторону |
| `5` | `10` | Минимум для размера — 10 мм |
| `0` | `10` | Ноль недопустим, поднимается до 10 |
| `Nx = 0`, `Ny = 0` | `1` | Ноль ячеек недопустим |
| `Nx = 2,7`, `Ny = 2,7` | `3` | Дробное количество округляется в большую сторону |

## 5.2 Ошибки

Значение больше 100 мм автоматически не уменьшается: введённое остаётся в поле, поле переходит в `Error`, показывается Error Block, переход блокируется.

## 5.3 Моменты проверки

При потере фокуса, при нажатии кнопки продолжения и перед каждым запуском генерации. Проверка перед генерацией обязательна независимо от предыдущих.

---

# 6. Шаг 2 — количество ячеек

Два поля: Nx и Ny, начальные значения 3 × 3. Только целые, минимум 1. Дробный ввод округляется в большую сторону, ноль поднимается до 1 (см. 5.1).

---

# 7. Ограничение габарита

Габарит модели считается точно (см. 12.4), поэтому ограничение накладывается на **реальный внешний размер**, а не на приблизительное произведение:

```
Nx × (ширина + 3,0) ≤ 500
Ny × (глубина + 3,0) ≤ 500
```

Проверка выполняется сразу после завершения изменения поля. При превышении: поле → `Error`, Error Block видим, переход и генерация блокируются.

Реальный габарит показывается пользователю постоянно, под превью.

---

# 8. Переход на третий шаг

1. Повторно проверяются все параметры.
2. При ошибках переход блокируется.
3. При корректных параметрах запускается генерация.
4. Пользователь переходит на третий шаг сразу, не дожидаясь генерации.
5. Третий шаг открывается в состоянии генерации.

---

# 9. Шаг 3 — модель

Содержит: 3D-превью, переключатель формы, поля размеров, поля количества, основную кнопку, кнопку сброса.

Превью интерактивное: вращение и масштабирование.

## 9.1 Первая генерация

Во время генерации: превью в `Loading`, параметры видимы но заблокированы, переключатель заблокирован, основная кнопка в `Loading`, кнопка сброса доступна.

После завершения: модель отображается, параметры разблокируются, кнопка становится `Скачать`.

## 9.2 Изменение параметров

Изменение значений **не запускает генерацию.** Старая модель остаётся в превью, кнопка меняется на `Обновить`.

Если пользователь вручную вернул все значения к параметрам последней успешной модели, кнопка снова становится `Скачать` без перегенерации. Сравниваются нормализованные значения.

## 9.3 Обновление

При нажатии `Обновить` параметры проверяются заново; при ошибке генерация не запускается. Во время генерации поля блокируются, кнопка в `Loading`, старая модель остаётся видимой, сброс доступен.

После успеха новая модель заменяет старую, её параметры становятся сохранёнными, кнопка становится `Скачать`.

# 10. Состояния основной кнопки

| Условие | Кнопка |
|---|---|
| Идёт генерация | Loading |
| Генерация завершилась технической ошибкой | Повторить |
| Параметры изменены, но невалидны | Обновить / Disabled |
| Параметры совпадают с параметрами модели | Скачать |
| Параметры изменены и валидны | Обновить |

Порядок строк — порядок проверки условий.

---

# 11. Превью

Состояния: `Loading`, `Ready`, `Error / Empty`.

**11.1** `Error / Empty` используется только когда готовой модели ещё не было ни разу.

**11.2** При ошибке обновления предыдущая успешная модель остаётся в обычном `Ready`.

**11.3** При замене модели ресурсы предыдущей освобождаются.

**11.4** Под превью — строка реального габарита в формате `Ш × Г × В мм` и количество ячеек.

# 12. Геометрия

## 12.1 Принцип

Модель строится **тайлингом одной плитки.** Плитка равна одной ячейке и по габариту совпадает с шагом сетки. Плитки стыкуются встык; стенки соседних плиток сливаются, из четырёх угловых уголков в узле получается крест, на краю — Т, в углу — Г.

Отдельных алгоритмов для краёв и углов не требуется. Это следствие конструкции исходной модели, а не упрощение.

## 12.2 Константы

| Параметр | Значение |
|---|---|
| Толщина стенки плитки | 1,5 мм (две соседние дают перегородку 3,0) |
| Толщина основания | 1,2 мм |
| Высота модели | 15,0 мм |
| Плечо стойки вдоль X | 5,0 мм |
| Плечо стойки вдоль Y | 7,0 мм |
| Фаска у подошвы стойки | 0,75 мм, 45° |
| Фаска сверху стоек | 0,5 мм, 45° (с Z = 14,5) |
| Фаска снизу проёма | 1,25 мм, 45° |
| Скругление выпуклых вертикальных рёбер | R 1,0 |
| Скругление вогнутых вертикальных рёбер | R 0,5 |

Константы вынесены в один модуль и в интерфейс не выводятся.

## 12.3 Построение плитки

Пусть `w` и `d` — введённые размеры полости, `t = 1,5`, `ax = 5,0`, `ay = 7,0`.

```
Габарит плитки:   W = w + 2t = w + 3,0
                  D = d + 2t = d + 3,0

Основание:        прямоугольник W × D
                  минус проём от (ax, ay) до (W − ax, D − ay)
                  выдавливание 0 … 1,2

Стойки:           в каждом углу плитки уголок из двух прямоугольников:
                  ax × t  вдоль X  и  t × ay  вдоль Y
                  выдавливание 0 … 15,0
```

Полка, на которую опирается баночка, получается сама: её ширина `ax − t = 3,5` вдоль X и `ay − t = 5,5` вдоль Y в каждом углу.

## 12.4 Построение сетки

```
Модель = ⋃  плитка, сдвинутая на (i × W,  j × D),   i < Nx,  j < Ny

Габарит = Nx × W  ×  Ny × D  ×  15,0
```

Объединение выполняется на плоских контурах, до выдавливания. Всего два выдавливания на всю модель: основание и стойки.

## 12.5 Требования к результату

- Замкнутый манифолд без самопересечений.
- Единицы — миллиметры.
- Модель в положительном октанте, нижняя грань на `Z = 0`.
- Печатается дном вниз без поддержек.

## 12.6 Отложено до бета-версии

Круглая форма ячейки с гексагональной упаковкой. Требует отдельной модели в Fusion и отдельного алгоритма: прямоугольной плитки при шестиугольной упаковке не существует, тайлинг из 12.4 неприменим.

# 13. Технический стек

| Задача | Решение | Обоснование |
|---|---|---|
| Сборка | Vite | Ноль конфигурации, статический вывод |
| Интерфейс | React | Логика раздела 10 и состояния экранов — конечный автомат с производными состояниями |
| Состояние | `useReducer`, одно дерево | Стейт-менеджер избыточен |
| Роутинг | Отсутствует | Шаг — поле в состоянии |
| Валидация | Собственная чистая функция | 5.3 требует одинакового результата в трёх точках вызова |
| Геометрия | `manifold-3d` (WASM) в роли 2D-контуров и выдавливания | Вся деталь описывается плоскими профилями: проверено по STEP, оси всех скруглений и фасок вертикальные. Трёхмерные булевы операции не нужны |
| Превью | three.js + OrbitControls | |
| Экспорт | Собственный код | Бинарный STL — 20 строк, 3MF — zip из трёх XML |
| Форматы | 3MF основной, STL дополнительный | 3MF хранит единицы, слайсер не угадывает масштаб |
| Стили | CSS-модули | Компоненты раздела 17 специфичны, UI-кит не даст ничего |
| Хостинг | Статика: Netlify, Vercel или GitHub Pages | Бэкенда нет |

**Web Worker — по результатам замера, не заранее.** Расчёт свёлся к объединению плоских контуров и двум выдавливаниям; на максимальной сетке он, скорее всего, уложится в десятки миллисекунд. Сначала измерить худший случай, и только если он превысит 50 мс — выносить в воркер. Тогда же появится и настоящая возможность прервать генерацию по `Сбросить`.

**Сознательно не используются:** сервер, база данных, очередь задач, аналитика, кэш моделей, роутер, стейт-менеджер, библиотека форм, CSS-фреймворк, библиотека анимаций, трёхмерное CSG-ядро.

# 14. Архитектура

## 14.1 Модули

```
state/       редьюсер, начальные значения, снимки параметров
validation/  нормализация и проверка, коды ошибок
geometry/    константы, профиль плитки, тайлинг
export/      STL, 3MF, имя файла
preview/     сцена three.js
ui/          компоненты раздела 17
```

## 14.2 Контракты

```js
// geometry
build({ width, depth, nx, ny })
  → { positions: Float32Array, indices: Uint32Array, bbox: {x, y, z} }

// validation
normalize(raw, kind) → string
validate(state) → { errors: string[], fields: Record<string, boolean> }

// export
exportSTL(mesh) → Blob
export3MF(mesh) → Blob
fileName(params, ext) → string

// state
snapshot(state) → string
buttonState(state) → 'download' | 'update' | 'retry' | 'loading' | 'disabled'
```

Сигнатура `build` не содержит формы ячейки. Когда появится круглая, добавляется параметр `shape` и второй модуль построения; остальное приложение не затрагивается.

## 14.3 Хранение состояния

До перезагрузки страницы хранятся: размеры, Nx, Ny, последняя успешная модель и снимок её параметров.

Модели постоянно не хранятся, истории нет. После перезагрузки, сброса или закрытия вкладки всё теряется.

# 15. Сброс, скачивание, выход

## 15.1 Сброс

Кнопка `Сбросить` доступна на третьем шаге всегда. Перед сбросом обязательно подтверждение. После подтверждения: генерация прерывается, модель и все данные удаляются, приложение возвращается на шаг 1 с начальными значениями раздела 3.

## 15.2 Скачивание

Начинается сразу, без подтверждения. Пользователь остаётся на третьем шаге, модель доступна для повторного скачивания, кнопка продолжает показывать `Скачать`.

Имя файла:

```
Nail_Modernism_Gelstand_[ширина]x[глубина]mm_[Nx]x[Ny].[ext]
Nail_Modernism_Gelstand_19.6x37mm_3x3.3mf
```

В имени файла точка, независимо от того, что показано в поле ввода.

## 15.3 Выход со страницы

При попытке обновить страницу, закрыть вкладку или уйти показывается системное предупреждение браузера.

> **Ограничение платформы.** Браузеры показывают диалог только после того, как пользователь взаимодействовал со страницей. На первом открытии без взаимодействия предупреждения не будет. Обойти нельзя.

Отдельный макет для системного диалога не требуется.

# 16. Ошибки

Текст ошибки **никогда не выводится внутри Input-компонента.** Поле переходит только в состояние `Error`, текст показывается отдельным Error Block. Блок поддерживает несколько причин одновременно. Тексты хранятся отдельным словарём.

| Код | Причина | Пример текста |
|---|---|---|
| ERR-01 | Поле размера пустое | Укажите размер. |
| ERR-02 | Размер больше 100 мм | Максимальный размер — 100 мм. |
| ERR-03 | Nx пустое | Укажите количество ячеек по оси X. |
| ERR-04 | Ny пустое | Укажите количество ячеек по оси Y. |
| ERR-05 | Превышение габарита по X | Уменьшите размер или количество ячеек по оси X. |
| ERR-06 | Превышение габарита по Y | Уменьшите размер или количество ячеек по оси Y. |
| ERR-07 | Превышение по X и Y одновременно | Оба сообщения в одном блоке |
| ERR-08 | Техническая ошибка первой генерации | Не удалось сгенерировать модель. Попробуйте ещё раз. |
| ERR-09 | Техническая ошибка обновления | Не удалось обновить модель. Попробуйте ещё раз. |
| ERR-10 | Тайм-аут генерации, 15 с | Не удалось завершить генерацию модели. Попробуйте ещё раз. |

Ситуации из 5.1 ошибками не являются.

## 17.1 Реализация полей ввода

`type="text"` с `inputMode="decimal"`, **не** `type="number"`: числовое поле в связке с запятой ведёт себя по-разному в разных браузерах и локалях. Нормализация по событию `blur`.

## 17.2 Пункт Soon

Пункт «Круглая» отрисовывается как неактивный: приглушённый текст, бэйдж Soon, курсор по умолчанию. Не получает фокус с клавиатуры, помечен `aria-disabled="true"`. Подсказки при наведении не требуется.

# 19. Адаптив и доступность

Mobile — самостоятельная компоновка, а не уменьшенная копия Desktop. Рекомендуемая: превью сверху на всю ширину, панель параметров под ним, кнопки закреплены внизу.

Обязательный минимум: видимый фокус на всех интерактивных элементах, `aria-invalid` на полях в `Error`, связка поля с Error Block через `aria-describedby`, `aria-disabled` на пункте Soon, учёт `prefers-reduced-motion` для лоадера.

Экраны 1 и 2 не должны требовать вёрстки, отдельной от экрана 3: набор полей один, различается видимость.

# 20. Критерии готовности

1. Открыть генератор без регистрации.
2. Увидеть переключатель формы с неактивным пунктом «Круглая» и бэйджем Soon.
3. Задать размеры.
4. Перейти на второй шаг.
5. Задать Nx и Ny.
6. Получить защиту от превышения габарита.
7. Запустить генерацию.
8. Увидеть состояние загрузки.
9. Получить превью.

# 22. Что подтверждено по STEP

Геометрия снята с двух файлов: сетка 3 × 3 и одиночная ячейка.

- Габарит сетки 67,8 × 120,0 × 15,0 при полости 19,6 × 37,0 и Nx = Ny = 3, что даёт `шаг = полость + 3,0`.
- Плитка одиночной ячейки — ровно 22,6 × 40,0 × 15,0, то есть равна шагу.
- Уровни Z: 0 / 1,2 / 1,7 / 14,5 / 15,0.
- Стенка плитки 1,5 мм, перегородка в сетке 3,0 мм.
- Все 216 цилиндрических и 216 конических поверхностей сетки имеют строго вертикальную ось. Это и есть основание для отказа от трёхмерного CSG.
